## 6. Idiomas: como funciona (necessário para qualquer tela nova)

- **Textos:** `src/i18n/messages/<locale>/<namespace>.json` (40 namespaces × pt-BR, en, es). O índice `src/i18n/messages/index.ts` é **gerado**: `node scripts/i18n-index.mjs && pnpm exec prettier --write src/i18n/messages/index.ts`. O teste `tests/unit/i18n.test.ts` exige as mesmas chaves e as mesmas variáveis ICU nos três idiomas.
- **pt-BR é a fonte e tem de ficar idêntico** ao que os e2e conferem; o navegador do e2e roda em pt-BR (`playwright.config.ts`).
- **Ordem de leitura:** texto pt-BR do código → arquivo do idioma → edições do banco (`platform_translations`), com cache de 30 s em `globalThis` (`src/core/i18n/store.ts`) limpo a cada edição.
- **Componentes cliente** só recebem os namespaces de `CLIENT_NAMESPACES` (`src/core/i18n/client-messages.ts`); um namespace usado em componente cliente precisa entrar ali.
- **Erros:** `AppError` tem `messageKey` (chave completa) e `messageValues`; ações de servidor usam `actionFailure(err)` / `localizeError` (`src/core/i18n/errors.ts`). A API e o MCP usam `englishErrorMessage` (`src/core/i18n/english.ts`): sempre inglês.
- **Metadados:** `generateMetadata` com `getTranslations`, nunca `metadata` estático em português. Datas e números com `getFormatter` / `useFormatter` (fuso America/Sao_Paulo).
- **Menu e módulos:** `translateNavigation` (`src/core/i18n/navigation.ts`) e o catálogo `moduleCatalog` (`src/core/i18n/modules.ts`). O manifesto continua em português como reserva.
- **Worker:** roda com `--conditions=react-server`; nunca importar o pacote raiz `next-intl` ali. Use `use-intl/core` (como `src/core/notifications/templates.ts`). Teste rápido: `timeout 60 node_modules/.bin/tsx --conditions=react-server -e 'import("./src/core/jobs/registry.ts").then(()=>console.log("ok"))'`.
- **Tradução automática (I6):** `src/core/i18n/machine/`; provedor por `TRANSLATION_PROVIDER=fake` (testes e e2e) ou pela chave `TRANSLATION_ANTHROPIC_API_KEY` (web e worker). Sem chave, os botões ficam desabilitados.

## 7. Armadilhas já encontradas

As do [handoff de 10/10](2026-10-10-handoff.md#5-armadilhas-já-encontradas) continuam valendo (seed antes de FORCE RLS, `revoke` de `anon`/`authenticated` em toda tabela nova, `WITH CHECK` que repete quem escreve, uma instrução por `$executeRawUnsafe`, auditoria com FK para empresas, `headers()` fora do `try`, Prettier só em arquivos limpos). Novas desta sessão:

1. **`app_migrations` é NOINHERIT:** depois de `alter function ... owner to app_rls_helper`, um `revoke`/`grant` feito como `app_migrations` **não tem efeito** (ele não é dono). Faça o `grant` antes da troca de dono, ou rode como o dono: `set local role app_rls_helper; ...; reset role;`. A I1 caiu nisso e a I5 corrigiu.
2. **Variáveis de contexto em políticas do helper** (`app.notification_email`, `app.platform_api_key_hash`): a função define e restaura o valor; documente por que outras funções do helper não ganham alcance.
3. **Worker e React:** importar `next-intl` (raiz) no caminho do worker quebra a subida em silêncio; no e2e, os jobs ficam presos e o `run-jobs` estoura 60 s.
4. **E2E e hidratação:** preencher um campo de componente cliente antes da hidratação pode voltar ao valor original. Use `page.waitForLoadState("networkidle")` e confira o valor com `toPass` antes de enviar (ver `e2e/languages.spec.ts`).
5. **E2E em modo estrito:** locators ambíguos quebram; prefira `exact`, escopo ou regex específica (por exemplo `/gdu_live_[0-9a-f]{64}/`).
6. **`console.log` do servidor não aparece no log do e2e;** para depurar use `console.error` e remova depois.
7. **`pkill -f playwright` mata o próprio shell.** Encerre processos por PID. Um PGlite órfão causa `EADDRINUSE` na porta 54398.
8. **Comandos longos** (e2e completo, cerca de 6 minutos) devem rodar em segundo plano com saída para arquivo; o tempo limite do shell corta execuções em pipe.
9. **Bancos paralelos:** agentes em paralelo usam cópias (`create database guidu_x template guidu`), nunca o mesmo banco.

## 8. Como validar localmente

O ambiente tem Postgres 16 em `/usr/lib/postgresql/16/bin`, Redis e Chromium em `/opt/pw-browsers`.

```bash
# 1. Banco local descartável (porta 54333, banco guidu): sobe o Postgres se
#    preciso, aplica todas as migrations, os seeds e as suítes SQL do CI.
AS_MIGRATIONS=1 bash scripts/local/rebuild-db.sh   # esperado: 31 PASS, nenhum FAIL

# 2. Redis local
redis-cli -p 6390 ping || redis-server --port 6390 --save "" --appendonly no --daemonize yes

# 3. Variáveis para testes de integração
export DATABASE_URL="postgresql://app_runtime:runtime@127.0.0.1:54333/guidu?connection_limit=5"
export DIRECT_DATABASE_URL="$DATABASE_URL"
export ADMIN_URL="postgresql://postgres@127.0.0.1:54333/guidu"
export MIGRATION_DATABASE_URL="$ADMIN_URL"
export WORKER_DATABASE_URL="postgresql://app_worker:worker@127.0.0.1:54333/guidu"
export REDIS_URL="redis://127.0.0.1:6390"

# 4. Aceite
pnpm typecheck && pnpm lint && pnpm test
APP_NAME=GUIDU APP_URL=http://localhost:3000 pnpm build
```

- `AS_MIGRATIONS=1` aplica a **última** migration como `app_migrations`, como no dev; `AS_MIGRATIONS=<arquivo>` escolhe outra.
- **E2E:** o `playwright.config.ts` sobe PGlite e um GoTrue falso (`e2e/support/`). Crie um `playwright.local.config.ts` temporário:

```ts
import base from "./playwright.config";
export default {
  ...base,
```
